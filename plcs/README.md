- plcs_1.c: start code, 提供了并行框架，但是未具体实现。
- plcs.c: 初次尝试，使用条件变量来控制线程，结果正确，但实现过于复杂，效果不佳。
- plcs_2.c: 使用信号量来控制线程，结果正确，效果一般（甚至打不过 plcs_0.c）。
- plcs_3.c: 突发奇想，将对角线变为连续内存，试图优化缓存问题，结果正确，效果优于前几个版本，但最多能实现2x加速，未能达到预期T倍加速。


### Something interesting
- 经过测试，发现当字符串长度超过50000后，多线程效果开始下降。对此，我的理解是，在plcs_3.c的存储方式中缓存局部性体现在对角线连续+前后对角线连续，当字符串过大，单个对角线过长时，内存无法存放下上一条对角线，导致多线程效果下降。当然，这不是多线程不如单线程的病因，多线程都缓存不够了，单线程肯定缓存也放不下，问题出在由于缓存废了，导致所有数据都要从内存中读取，而单线程只要自己读取，而多线程是所有线程都要读取，内存带宽不够用了，交通堵塞，以至于CPU空转等待数据（实际top观察到CPU使用率确实下降）。
